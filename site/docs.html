Events and automations

Every active alarm and reminder has its own event entity next to its state sensor and its acknowledge button, for example event.alex_low_alarm (Low alarm). The report has the event entity Report. Automations use the trigger Event received with one or more event types:

Event typeFires when
<alarm>_alertthe alarm starts and on every repeat
<alarm>_endedthe alarm is acknowledged or over
<change>_soonthe warning of a change reminder
reporta report period ends

The event types are unique per person, so an automation can target the entity or the whole device of the person. The values of an event are the attributes of the entity, in templates trigger.to_state.attributes.<name>; the event type is trigger.to_state.attributes.event_type. 

triggers:
  - trigger: event.received
    target:
      entity_id: event.alex_low_alarm
    options:
      event_type:
        - low_alert
actions:
  - action: notify.mobile_app_your_phone
    data:
      title: "{{ trigger.to_state.attributes.title }}"
      message: "{{ trigger.to_state.attributes.message }}"

The state sensors of the alarms are for dashboards and conditions; they do not change on a repeat, so they are not suited as triggers.

Values of the alarms

All alarm and reminder events have these attributes; values that do not apply are empty.

Alarms and reminders

    Report

    Entity Report, event type report.

    When it fires

      Values

      Acknowledge and pause

      • Acknowledge silences an alarm for its snooze time; then it is checked again and starts at once if it still applies. Ways: the Acknowledge … button, the action blood_glucose_monitor.acknowledge or a notification action with the id from ack_action.
      • Pause alarms silences all alarms except urgent low for the configured duration and turns off by itself.
      • Record a change of cannula, sensor or reservoir with the … changed button or the action blood_glucose_monitor.record_change (optionally with a time in the past).
